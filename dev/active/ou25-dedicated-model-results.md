## Interpretation

### 1. The mechanical ship gate is misleading on this holdout

The gate compares `ou25_dedicated_v1` vs `v14_recreate_2026_05_11` on the full holdout: +3.12% log_loss + 2.63pp ROI@+5% → passes (≥2pp ROI gate clears).

**But** the per-era split shows the win is concentrated in AF-era (n=213), driven by `v14_recreate_2026_05_11` being substantially worse on this universe (log_loss 0.7623 vs 0.6650 for `v20260524_market` on the same 213 matches). On the larger CSV-era subset (n=1280), `ou25_dedicated_v1` is *worse* than `v14` (log_loss 0.6947 vs 0.6891) and only marginally better than `v14_recreate` on ROI (+2.05% vs +3.05% — actually slightly worse).

The win is real but is a win against the wrong opponent.

### 2. The OU-CLV-OPTION-B-FLIP override is suspect on this universe

The override (set 2026-06-07) pins OU inference to `v14_recreate_2026_05_11`. Its rationale was OU-CLV-OPTION-C-DIAG's finding that `v20260524_market` was +1.4% worse on OU log_loss than `v14` on a narrow 2026-05-17→05-31 eval window.

This evaluation, on a 1,493-match holdout from a different universe (football-data.co.uk mature European leagues), shows the *opposite*:

- `v20260524_market` log_loss = 0.6930 (best non-Pinnacle)
- `v14_recreate_2026_05_11` log_loss = 0.7179 (worst non-Pinnacle)
- `v20260524_market` ROI@+5% = +11.23%
- `v14_recreate_2026_05_11` ROI@+5% = +2.89%

**Both findings can be simultaneously true**: the OU regression caused by TIER-C-EXPAND likely lives in low-tier leagues that football-data.co.uk doesn't cover. On mature European leagues, `v20260524_market` is excellent. The current env override is solving a tier-specific problem with a universe-wide model swap — and probably hurting performance on the majority of fixtures.

### 3. `ou25_dedicated_v1` is not the right deployment target

Even if the OU-CLV-OPTION-B-FLIP override is reversed, `ou25_dedicated_v1` is dominated by `v20260524_market` on this universe by a wide margin. The dedicated model's 9-feature sparse-corpus training cannot match the 51+ feature production model when production has the data it needs.

The dedicated model's primary value is as a **fallback for matches where rich MFV features are unavailable** — which is most CSV-era data and some recent matches with feature pipeline gaps. It is not a strict replacement for the production OU head.

## Verdict

**SHELVE** — do not flip `MODEL_VERSION_OU` to `ou25_dedicated_v1`.

But this task surfaces a more important finding:

### Recommended follow-up tasks

1. **`OU-CLV-OPTION-B-RE-EVAL`** (P1, target this week) — re-examine the OU-CLV-OPTION-B-FLIP decision. The mature-European universe shows `v20260524_market` is materially better than `v14_recreate_2026_05_11` for OU. Re-run the OU-CLV-OPTION-C-DIAG on per-tier subsets:
   - If `v20260524_market` is only worse on TIER-C-EXPAND leagues (T3+), the right fix is *not* a universe-wide override but per-tier routing or excluding TIER-C from training.
   - If `v20260524_market` is also worse on T1/T2, the override is justified — but then there's something different about live betting cohorts that this eval doesn't capture.

2. **`OU-LONGTERM-EXCLUDE-TIERC-FROM-OU-TRAINING`** (already filed, P1) — the structural fix: modify `workers/model/train.py` to allow per-market league filtering. The OU head trains on the pre-TIER-C league set; 1X2/AH/BTTS continue on the full universe. Removes the env-var override permanently.

3. **`OU-EVAL-BY-TIER`** (new follow-up, ~2h) — re-run `train_ou25_dedicated.py` style eval on AF-era matches stratified by `league_tier` to localise where each bundle wins/loses. Would give clean evidence to drive the override decision.

4. **`ou25_dedicated_v1` as fallback** — the bundle is saved at `data/models/soccer/ou25_dedicated_v1/` and is production-loadable. Consider routing to it as a degraded-mode fallback when full MFV features are missing, rather than as a primary OU head.
